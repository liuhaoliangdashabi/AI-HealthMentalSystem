## 1. 先定端口，再下载

**这一步不能跳过。** Spring Cloud 这套中间件的默认端口，和你的项目（8080）有两处直接冲突。

| 服务 | 默认端口 | 你的规划 | 说明 |
|---|---|---|---|
| 你的项目 | 8080 | **8080** | 不动 |
| Nacos API | 8848 | 8848 | 服务注册/配置读写 |
| Nacos gRPC | 9848 | 9848 | 2.x 起新增，客户端长连接用 |
| **Nacos 控制台** | **8080** ⚠️ | **8888** | **3.0 新特性，控制台独立端口，必须改** |
| **Sentinel Dashboard** | **8080** ⚠️ | **8858** | 启动时加参数改 |
| RocketMQ NameServer | 9876 | 9876 | 路由中心 |
| RocketMQ Broker | 10911 | 10911 | 消息存储 |
| Redis | 6379 | 6379 | 已有 |
| MySQL | 3306 | 3306 | 已有 |

**为什么 Nacos 3.0 控制台是 8080**：3.x 把「数据面」（8848，API）和「控制面」（8080，Web 控制台）拆开了。
2.x 时代控制台是 `http://localhost:8848/nacos`，3.x 变成 `http://localhost:8080`。
网上大量教程还是 2.x 的写法，照着做会找不到控制台。

## 4. 安装步骤

### 4.1 Nacos（约 10 分钟）

**① 解压到没有中文和空格的路径**

```
D:\dev\nacos
```

❌ `C:\Users\HP\Desktop\学习资料（真的学习资料）\nacos` —— 路径带中文和空格，
Nacos 启动脚本在某些情况下会解析失败。

**② 改控制台端口（关键）**

编辑 `conf/application.properties`，在文件末尾加：

```properties
nacos.console.port=8888
```

**③ 单机模式启动**

```cmd
cd D:\dev\nacos\bin
startup.cmd -m standalone
```

`-m standalone` 必须加，不加会按集群模式启动然后报错。

**④ 验证**

浏览器打开 http://localhost:8888 ，能看到登录页就是成功。

默认账号密码都是 `nacos`。

> **如果启动失败，先看 `logs/start.out`。**
> Nacos 3.x 对鉴权配置比 2.x 严格，如果报 `token.secret.key` 相关的错误，
> 在 `conf/application.properties` 里加一行（32 位以上）：
> `nacos.core.auth.plugin.nacos.token.secret.key=SecretKey012345678901234567890123456789012345678901234567890123456789`

**⑤ 停服务**

`bin/shutdown.cmd`，或者直接关掉那个 cmd 窗口。

---

### 4.2 RocketMQ（约 30 分钟，Windows 上最麻烦的一个）

**① 解压到没有中文和空格的路径**

```
D:\dev\rocketmq
```

解压后目录结构是 `D:\dev\rocketmq\bin`、`D:\dev\rocketmq\conf`、`D:\dev\rocketmq\lib`。
**注意别解压成 `D:\dev\rocketmq\rocketmq-all-5.3.1-bin-release\bin` 这种多套一层**，
后面配环境变量容易错。

**② 设环境变量**

```
ROCKETMQ_HOME = D:\dev\rocketmq
```

设完**重新打开一个 cmd 窗口**才生效（旧窗口读不到新变量）。

**③ 改内存（这一步不做，90% 起不来）**

RocketMQ 的启动脚本默认给 JVM 分配 **8GB 堆内存**，普通笔记本直接 OOM 或启动失败。

编辑 `bin/runbroker.cmd`，找到这一行：

```cmd
set "JAVA_OPT=%JAVA_OPT% -server -Xms8g -Xmx8g -Xmn4g"
```

改成：

```cmd
set "JAVA_OPT=%JAVA_OPT% -server -Xms512m -Xmx512m -Xmn256m"
```

再编辑 `bin/runserver.cmd`，找到：

```cmd
set "JAVA_OPT=%JAVA_OPT% -server -Xms4g -Xmx4g -Xmn2g"
```

改成：

```cmd
set "JAVA_OPT=%JAVA_OPT% -server -Xms512m -Xmx512m -Xmn256m"
```

**④ 启动 NameServer（先启这个）**

```cmd
cd D:\dev\rocketmq\bin
mqnamesrv.cmd
```

看到这行就是成功：

```
The Name Server boot success. serializeType=JSON, address 0.0.0.0:9876
```

⚠️ 这个窗口**不能关**，关了就停了。想后台跑用 `start mqnamesrv.cmd`。

**⑤ 启动 Broker（再启这个）**

**新开一个 cmd 窗口**：

```cmd
cd D:\dev\rocketmq\bin
mqbroker.cmd -n 127.0.0.1:9876
```

看到这行就是成功：

```
The broker[broker-a, 192.168.x.x:10911] boot success. serializeType=JSON and name server is 127.0.0.1:9876
```

5.x 的 broker 会**同时启动 Proxy**（日志里能看到），不需要单独起 `mqproxy`。
客户端用 4.x 的 remoting 协议（Spring Cloud Stream RocketMQ 用的就是它）可以直接连。

**⑥ 验证（用自带的命令行工具）**

**再开一个 cmd 窗口**：

```cmd
set NAMESRV_ADDR=127.0.0.1:9876
cd D:\dev\rocketmq\bin
mqadmin.cmd clusterList
```

能看到 `broker-a` 的集群信息，说明整条链路通了。

**⑦ 发一条测试消息（可选）**

```cmd
set NAMESRV_ADDR=127.0.0.1:9876
tools.cmd org.apache.rocketmq.example.quickstart.Producer
```

控制台会刷一堆 `SendResult`，说明消息发出去了。

### 4.3 Sentinel Dashboard（约 5 分钟）

**一个 jar，不用解压，不用改配置。**

```cmd
cd D:\dev
java -Dserver.port=8858 -jar sentinel-dashboard-1.8.9.jar
```

`-Dserver.port=8858` 必须加，否则默认 8080 和你的项目冲突。

浏览器打开 http://localhost:8858 ，账号密码都是 `sentinel`。

**注意**：刚启动时控制台是空的，因为还没有任何服务接入。
等你的项目加了 `spring-cloud-starter-alibaba-sentinel` 依赖并启动后，左侧才会出现服务名。

### 4.4 Seata（可选，最后再装）

Seata 比前三个麻烦，需要：

1. 先建一个 `seata` 库，导入官方 SQL（`script/server/db/mysql.sql`）
2. 改 `conf/application.yml`，配数据库连接、注册中心地址（指向 Nacos）
3. 启动 `bin/seata-server.bat`

## 6. 常见坑

| 坑 | 症状 | 解法 |
|---|---|---|
| **Nacos 控制台打不开** | 访问 8848/nacos 是 404 | 3.x 控制台在 8080，你改成了 8888，访问 8888 |
| **Nacos 启动即退出** | `start.out` 里报鉴权/密钥错误 | 补 `token.secret.key`（见 4.1 ④） |
| **Nacos 没加 `-m standalone`** | 日志刷 `Nacos started successfully in cluster mode` 然后卡住 | 加 `-m standalone` |
| **RocketMQ broker 起不来** | 日志空白 / 直接退出 | 改 `runbroker.cmd` 的 `-Xms8g`，见 4.2 ③ |
| **RocketMQ 提示找不到主类** | `Could not find or load main class` | `ROCKETMQ_HOME` 没设，或设完没重开 cmd |
| **RocketMQ 路径带中文/空格** | 启动脚本解析失败 | 换到 `D:\dev\` 这种纯英文路径 |
| **Sentinel 起不来** | 8080 被占用 | 加 `-Dserver.port=8858` |
| **Sentinel 控制台空白** | 登录后什么都没有 | 正常，要等服务接入才显示 |
| **关了 cmd 窗口服务就停** | —— | 用 `start xxx.cmd` 后台启动，或写成 bat 脚本 |

## 7. 装完之后

四个服务同时跑，内存占用大概：

| 服务 | 内存 |
|---|---|
| Nacos | ~500MB |
| RocketMQ NameServer | ~200MB |
| RocketMQ Broker | ~600MB |
| Sentinel | ~200MB |
| 合计 | **约 1.5GB** |

8G 内存的机器能跑，但加上 IDEA + 你的 Spring Boot 项目会比较紧张。
建议学习时**按需启动**：学注册中心只开 Nacos，学 MQ 再开 RocketMQ。

## 附：启动顺序速查

```cmd
:: 1. Nacos（最先，注册中心是基础）
cd D:\dev\nacos\bin && startup.cmd -m standalone

:: 2. RocketMQ NameServer
cd D:\dev\rocketmq\bin && mqnamesrv.cmd

:: 3. RocketMQ Broker（等 NameServer 起来后再启）
cd D:\dev\rocketmq\bin && mqbroker.cmd -n 127.0.0.1:9876

:: 4. Sentinel Dashboard
cd D:\dev && java -Dserver.port=8858 -jar sentinel-dashboard-1.8.9.jar

:: 5. 你的项目（8080）
```

**顺序不能反**：NameServer 没起来，Broker 注册不上去；Nacos 没起来，服务注册会一直重试。

## 8. 在第二台电脑复刻同一套环境

**不要重跑一遍安装流程。** 踩过的坑没必要踩第二次，直接把已经调好的目录搬过去。

### 8.1 要拷什么

| 拷什么 | 大小 | 说明 |
|---|---|---|
| `C:\dev\nacos` | 205 MB | 已改好端口和鉴权密钥 |
| `C:\dev\rocketmq` | 92 MB | 已改好内存参数和 broker.conf |
| `C:\dev\downloads`（可选） | 305 MB | 只为了以后重装，不拷也行 |

两个目录合计约 **297 MB**，U 盘或局域网共享都能过。

### 8.2 目标机器必须满足的条件

| 条件 | 为什么 |
|---|---|
| **JDK 17 或以上** | Nacos 3.x **强制**要求 JDK 17，2.x 才支持 JDK 8。这是最容易漏的一条 |
| 路径同样是 `C:\dev\` | `broker.conf` 里 `storePathRootDir` 写死了绝对路径，换盘符要改 |
| 端口 8848 / 8888 / 9848 / 9876 / 10911 空闲 | 用 `netstat -ano \| findstr "8848"` 检查 |

### 8.3 拷完要做的三件事

**① 重设环境变量**（用户级，拷不过去）

```powershell
[Environment]::SetEnvironmentVariable("ROCKETMQ_HOME", "C:\dev\rocketmq", "User")
[Environment]::SetEnvironmentVariable("NACOS_HOME", "C:\dev\nacos", "User")
```

设完**必须重新开一个 cmd 窗口**才生效。

**② 如果路径不是 `C:\dev`，改三处**

```
rocketmq/conf/broker.conf        → storePathRootDir / storePathCommitLog
```

`brokerIP1 = 127.0.0.1` 只允许本机连接。如果两台电脑要互相访问（比如服务注册到对方机器上的 Nacos），
把它改成局域网 IP，比如 `brokerIP1 = 192.168.1.20`。

**③ 清掉第一次跑残留的数据**（可选）

```cmd
rmdir /s /q C:\dev\rocketmq\store
rmdir /s /q C:\dev\nacos\data
```

`nacos\data` 里是 Derby 内嵌库（存配置和用户），拷过去会带着上一台机器的数据。
想要干净环境就删掉，Nacos 启动时会自己重建。

### 8.4 两台机器同时跑会不会冲突

**不会。** 端口冲突只在同一台机器上才有意义，两台电脑各用 8848 互不影响。

但如果服务要跨机器注册，注意：
- Nacos 集群模式才需要 `cluster.conf`，你现在是 standalone，两台就是两个独立集群
- 项目里 `spring.cloud.nacos.discovery.server-addr` 要指向正确的 IP，不能写 `localhost`

### 8.5 一句话总结

拷目录 → 装 JDK 17 → 设两个环境变量 → 起 Nacos → 起 NameServer → 起 Broker。
中间那些改配置、改内存的步骤全部跳过，因为已经改好了。
