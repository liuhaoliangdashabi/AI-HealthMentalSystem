## 文章封面清理（knowledge → file）

### 前置决定
- **不新增 `by-business` 接口**，直接复用 `/internal/file/by-key`。
- `FileService.deleteByObjectKey` **去掉 `upload_user_id` 过滤条件**：文章封面可能是管理员代传的，按作者 id 匹配会 0 行、静默不删。秒传已关，一个 key 唯一对应一条记录，按 key 删安全。`userId` 参数保留，只落日志。
- **不加 `@GlobalTransactional`**：删 OSS 不可回滚，套事务反而会造成「库回滚了、文件没了」的破图。顺序固定为「先改库、后删文件」，失败只 `log.warn`。
- `ArticleService.deleteById`（注销级联）**不动**：它在全局事务里，塞 HTTP 调用会多一个分支失败点。漏掉的是「管理员代传的封面」，属成本问题不是数据事故，留给日后对账任务。

### 改动（已编译通过 BUILD SUCCESS）
| 文件 | 改动 |
|---|---|
| `file-service/.../FileService.java` | `deleteByObjectKey` 删掉 `.eq(getUploadUserId,userId)` 一行 |

| `knowledge-service/.../ArticleService.java` | 注入 `FileClient`；`putArticleDetail` 先 `selectById` 拿旧值再 `updateById`；`deleteArticle` 先查 cover 再删；新增私有 `deleteCover` 吞异常 |

### 关键坑
- `putArticleDetail` 的清旧图条件必须三段与：`newCover != null` && `!isBlank()` && **`!newCover.equals(old.getCoverImage())`**。第三段不能省 —— 前端编辑时常把当前封面原样回传，少了它会把正在用的图删掉，直接破图。
- `selectById` 必须在 `updateById` 之前，否则 `cover_image` 已被覆盖，旧 key 永久丢失。

## 验证码：确定不做
- 用户决定跳过图形验证码，代码一行未写（`captchaTicket` 字段也没加），无需回滚。
- 易盾有免费试用，但：7 天 / 1000 次每小时 / 1 个可用 ID / 带易盾 logo / 申请需客服审核约 1 个工作日，商用报价约一万元一年 —— 成本远高于收益。
- 说法定调：**登录防护 = 服务端 Redis ZSet 滑动窗口限流 + 账号拉黑**（`UserService.login` 已有），图形验证码属前端交互层加固，不纳入本期范围。

## 实测结果（15:20，四个服务全启动）
| 场景 | 做法 | 结果 |
|---|---|---|
| 换头像 | `PUT :8050/api/user/avatar`，把 user1 头像从 `avatar/2026/11/09/5db33...jpg` 换成 `avatar/2026/11/02/9b84ac...jpg` | ✅ 旧记录 id=100 消失、该 key 剩余记录 0、OSS 旧文件 HEAD 变 **404** |
| 删文章清封面 | 插一条探针 `sys_file_info`(file_path=`article/test/delete-probe.jpg`) + 插探针文章 `probe-del-0001` 指向它 → `DELETE :8020/api/knowledge/article/probe-del-0001` | ✅ 文章没了、探针文件记录**被 file-service 删掉**（证明 Feign 全链路通）、真实文章封面与 OSS 文件均未受影响（HEAD 200） |
| 注销打标 | 插 2 条 `upload_user_id=999999` 的探针记录 → `DELETE :8060/internal/file/by-user?userId=999999` | ✅ 返回 2，两条 `is_temp` 均变 1 |
| 定时清理 | 未验 | ⏳ `FileCleanupTask` cron `0 */20 * * * ?`，条件 `is_temp=1 and create_time < now-10min`，要等一轮；验法：临时改 `0 */1 * * * ?` |

- 测试用探针数据已全部清空（`upload_user_id=999999` 已删，探针文章已删），真实数据只动了 user1 头像（属于正常换头像行为）。
- 用 `mysql --default-character-set=utf8mb4 -N -r` + `JSON_OBJECT` 拼请求体可避免中文乱码/转义问题；但文章更新接口 `@Size(max=5000)` 对长 content 会返回 4002「请求体格式不正确」，所以改用「插探针文章 + 删文章」这条路验封面。
