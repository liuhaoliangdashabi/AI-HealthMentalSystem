## 今日踩的坑（都已修）
1. **diary-service 启动失败 `OpenAI API key must be set`**：pom 里误加了 `web` 模块依赖 → 传递带入 `spring-ai-starter-model-openai` → 自动配置造 OpenAiChatModel。删掉 `web` 依赖即好（Result/BusinessException 来自 `common`）。
2. **`/api/emotion-diary/page` 返回默认 404 JSON**：`target/classes` 里的 DiaryController 只有 admin 两个映射 → 源码改了没重编译/没重启。诊断法：`grep -a -o "emotion-diary[^\"]*" xxx.class`。
3. **越权删除返回 HTTP 500 默认 JSON**：diary-service 主类只有 `@SpringBootApplication`，没扫 `org.example.common`，`GlobalExceptionHandler` 未注册 → BusinessException 无人接。已改成 `scanBasePackages={"org.example.diaryservice","org.example.common"}`（与 knowledge-service 对齐）。
4. **`roleType.equals(2)` 在 header 缺失时 NPE**（同样表现为 500）：改成 `Integer.valueOf(2).equals(roleType)`，并在 Controller 加 `checkIdentity` 拒绝缺 header 的请求。
5. **Redis `Command timed out after 500ms`**（web 13:41 三个定时任务同时报）：Redis 当时健康（master+2 从、哨兵认 6379），属瞬时卡顿。诱因是 `spring.data.redis.timeout: 500ms` 过紧 + Windows(MSYS) 版 Redis 的 RDB 落盘 + 内存吃紧（15.7G 被 RocketMQ 两 JVM 占 4G）。建议改 3000ms。任务侧失败都会重新入 dirty 集合，不丢数据。

## 日志分级约定（本次改动）
- 越权（记录存在但不是你的）→ `log.warn`，抛 `BusinessException(A0300,"无权操作他人的日记")`
- 真不存在（前端传错 id）→ `log.error`，抛 `BusinessException("日记不存在")`（6000）
- 缺身份 header（绕过网关）→ `log.warn`，401
- 实现上必须「先 selectById 再 deleteById」，因为 `delete()` 返回 0 无法区分不存在和越权。
