**判断口诀**：

| 状态码 | 含义 | 查哪里 |
|---|---|---|
| **401** | 过滤器拦了 | token / 白名单 / 签名 |
| **404** | 网关没有路由匹配 | routes 的 Path |
| **503** | 有路由，连不上后端 | 后端没起 / 端口错 / Nacos namespace+group |
| **200 + `code:B0120`** | 转发成功，但目标服务没这个接口 | 该搬 Controller 了 |

### D1：gateway 模块 ✅

**实际建的文件**

```
gateway/
├── pom.xml
└── src/main/
    ├── java/org/example/gateway/
    │   ├── GatewayApplication.java
    │   └── AuthGlobalFilter.java        （与启动类同包，没建 filter 子包）
    └── resources/application.yml
```

**依赖（5 个 + 1 可选）**：`spring-cloud-starter-gateway-server-webflux`、`spring-cloud-starter-loadbalancer`、`spring-cloud-starter-alibaba-nacos-discovery`、`java-jwt`、`lombok`、`caffeine`（消 WARN 用）

**最终 yml**

```yaml
server:
  port: 9000

jwt:
  secret: ${JWT_SECRET}
  header: token

spring:
  application:
    name: gateway
  cloud:
    gateway:
      server:
        webflux:                    # 4.3 起按技术栈分家，旧 key 是 spring.cloud.gateway.routes
          routes:
            - id: knowledge-service # 必须写在前面，网关按顺序匹配，第一个命中就停
              uri: lb://knowledge-service
              predicates:
                - Path=/api/knowledge/**
            - id: web               # 过渡期兜底，D13 自然消失
              uri: http://127.0.0.1:8080
              predicates:
                - Path=/api/**
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848
        namespace: dev
        group: dev
        register-enabled: false     # 网关不注册自己，没人会写 lb://gateway
```

**过滤器的三条硬规则**

1. `implements GlobalFilter, Ordered`，`getOrder()` 返回 `-100`。**不能照抄 web 的 `JwtAuthticationFilter`** —— 它用 `HttpServletRequest`，WebFlux 里没这个类。
2. claim 名是 **`userId`**（不是 `id`），取数字用 `asLong()` 再 `String.valueOf()`。用 `asString()` 在 java-jwt 4.x 上取数字会返回 null。
3. `mutate().header()` 本身就是覆盖语义，客户端伪造的 `X-User-Id` 会被冲掉。

**白名单**：`/api/user/login`、`/api/user/add`、`/error`
⚠️ **绝对不能放 `"/"`** —— 所有路径都以 `/` 开头，`startsWith` 会永远命中，等于全部放行，而且不报错。

**验收证据**：`curl -i localhost:9000/api/knowledge/article/hot` → `HTTP/1.1 401`，body 长度 62。

**核心教训：跨模块拆分 = Copy，同模块内整理 = Move**

IDEA 的 Move 重构假设「所有代码在同一个编译单元里，改个 import 就能自洽」。拆微服务的前提是**模块之间不能互相依赖**，所以 Move 必然把依赖撕成两半 —— 两边一起红。

| 场景 | 动作 |
|---|---|
| 同一个模块里整理包结构 | Move |
| 搬到独立部署的模块 | **Copy**，老的先留着 |

什么时候删老的？**新服务跑通 + 前端切过去 + 观察没问题之后**。现在 `KnowledgeArticle` 在两个模块各有一份，是**正确状态**。

**包名统一为** `org.example.knowledgeservice.*`，与 web 的 `org.example.aispringboot.*` 完全隔离。

### D4：article 查询三接口 + 跨域解耦 ✅

**四个跨域决策（都验证了）**

| # | 原依赖 | 处理 | 结果 |
|---|---|---|---|
| 1 | `userMapper.selectBatchIds` / `selectById`（跨库查作者名） | 加冗余字段 `author_name`，跨 schema `UPDATE JOIN` 回填 | 7 篇全回填成「系统管理员」 |
| 2 | `OSSUtil.getUrl` | 内联 `buildCoverUrl`，yml 补 `oss.region`/`oss.bucket` | 不复制 OSSClient 和 AccessKey |
| 3 | `UserType.ADMIN` + `user.getUserType()` | `@RequestHeader("X-User-Role") Integer roleType` | `Integer.valueOf(2).equals(roleType)`，null 安全 |
| 4 | `ArticleContentService` | 一起复制，SpEL 里的 `T(...)` 手动改包名 | 编译不报、只在运行时炸，必须手动改 |

**验收证据**：详情 / 列表 / 热门榜 / 分类树 四条过网关全 200；无 token 401；`grep aispringboot` = 0。

**D4 踩的三个坑（都已修）**

1. **缓存串台**：两个服务共用 `article::<id>`，`GenericJackson2JsonRedisSerializer` 把类名写进 `@class`，web 写的缓存 knowledge-service 读不出来 → `Cannot locate class`。修法：`computePrefixWith(cacheName -> "ks:" + cacheName + "::")`。
2. **`unless` 的 `&&` 写成 `||`**：`#result==null && #result.status...` 在 null 时继续求值右侧 → SpEL NPE → 查不存在的 id 返回 500「系统繁忙」。应该是 `||`。
3. **`@Value("${oss.bucket}")` 抄给了 `ossRegion`**：因为 7 篇文章封面都是空串，`buildCoverUrl("")` 直接短路，bug 一直没暴露。

**顺带清掉的历史债**：Redis 被 `FLUSHDB` 过一次，`stream:ai:task` 的消费者组跟着没了 → `AiTaskConsumer.consumeAiTask`（无 try/catch，每 800ms）刷 `RedisSystemException: Error in execution`。修法：`XGROUP CREATE ... MKSTREAM` 或重启 web。教训：**清缓存只用 `--scan --pattern` 精确删**。

**新发现并当场修掉的 bug：`knowledge-service` 缺 `MpConfig` → 分页静默失效**

这个 bug 从 D4 就存在，一直没被发现，因为验收只看「返回了真实文章」，没看 `total`。

症状：`GET /article/page?size=2` 返回 **全部 9 条**，`total=0`、`pages=0`。前端表现就是「一页塞满所有数据 + 分页器显示 0 条」。

根因：MyBatis-Plus 的 `PaginationInnerInterceptor` 没注册。**没有它 `selectPage` 不报错，只是不去 count、不加 LIMIT** —— SQL 原样执行，`page.getTotal()` 停在默认值 0。又是个「静默降级」。

修法：把 web 的 `config/MpConfig.java` 复制到 `knowledge-service/.../config/`，改包名。修完实测 `size=2 → 2 条 / total=7 / pages=4`。

> **记进心里**：D3 复制配置类时只数了 `RedisConfig`、`CacheConfig` 两个，`MpConfig` 是第三个。以后复制「配置类」要 `ls` 整个 config 目录，别凭记忆数。

> **两个知识点，比改动本身值钱：**
>
> 1. **锁必须在 `validate()` 之前上。** 校验是异步的，如果写成「校验通过后再上锁」，30ms 后的第二次 `keyup` 进来时 `loading` 还是 `false`，照样放行 —— 异步动作之间就是穿透窗口。代价是校验失败要手动解锁（放在 `if(!valid)` 里），忘了就是「输错一次密码，按钮永远转圈」。
> 2. **`:loading` 管不住回车。** 它只挡鼠标点击和给视觉反馈；`keyup` 事件挂在 `el-form` 上，根本不经过按钮。真正挡住重复请求的是 `if(loading.value) return` 这一行。两套机制各管一条路。

**这里有个坑必须记住**：前端锁只能防手抖，**防不了刷**。脚本直接打 `/api/user/login` 不经过浏览器。真要防暴力登录得在后端做（IP/账号计数、失败锁定、验证码），长远靠 Sentinel 限流。**别把前端锁当成安全措施。**

### 4.0 跨域依赖的通用拆法（方法论）

拆微服务真正的工作量不在搬代码，在**把依赖图拆成单向无环**。

#### 第一步：画出依赖图，找环

```
knowledge ──要作者名──→ user
knowledge ──要封面URL──→ file(OSS)
diary     ──要用户ID──→ user
consult   ──要用户ID──→ user
user      ──什么都不需要──→  ∅
```

**`user` 被三个域依赖，是中心节点。** 所以它必须**最后**拆（D9）—— 先拆它，等于同时改三个调用方。

**拆的顺序原则：从叶子往中心拆。** 谁被依赖得越少，越早拆。

#### 第二步：选「断点」

环上必须断一处，断点选在**业务上最不重要的那条边**。本项目里：

| 边 | 业务重要性 | 断法 |
|---|---|---|
| knowledge → user（只要一个显示名） | 低，显示错了不影响业务 | 冗余字段 |
| knowledge → file（只要拼 URL） | 低，纯字符串拼接 | 内联 |
| diary → user（要 userId） | 低，网关已经透传了 | header |

**注意**：`user` 本身不依赖任何服务，所以这个图**其实没有环**。真正麻烦的环长这样：`A → B → A`（比如订单要查库存，库存要查订单）。遇到环，只能靠「事件驱动」或「把环上两个服务合并」来破。

#### 第三步：三种断开手段，按耦合强度选

| 手段 | 做法 | 什么时候用 | 代价 |
|---|---|---|---|
| **① 数据冗余** | 把对方的关键字段复制一份到自己库 | 读多写少、**允许短暂不一致** | 要处理同步（MQ 事件 / 定时任务） |
| **② 同步调用** | Feign / RPC 实时问对方 | **必须实时准确**（如余额、库存） | 依赖对方可用性，必须配超时 + 熔断 + 降级 |
| **③ 异步事件** | 对方发 MQ，自己订阅更新本地副本 | 可以延迟几秒 | 复杂度最高，要保证不丢不重 |

**判断口诀，按顺序问三句**：

1. 「这个字段显示错了，用户会损失钱吗？」→ 会 → **② 同步调用**
2. 「晚 5 秒更新，业务能接受吗？」→ 能 → **③ 事件**（或定时任务）
3. 都不涉及 → **① 冗余**，最简单

#### 第四步：冗余字段的「三个必须」

选冗余不是甩手不管，必须同时想清楚三件事：

| 必须 | 本项目怎么做 |
|---|---|
| **写入时必须同时写** | `createArticle` 时把 `author_name` 一起 insert（D5） |
| **存量必须回填** | 跨 schema `UPDATE ... JOIN` 一次性刷 |
| **变更时必须同步** | 用户改昵称 → 发 `user.changed` 事件 → knowledge-service 更新（D9 做，现在接受不一致） |

**面试可以这么说**：冗余字段是「读扩散」的代价换「读性能」，本质是把 JOIN 从查询时挪到了写入时，用**最终一致**换**查询不跨库**。

#### 本项目已经用过这套方法的证据

| 场景 | 手段 | 位置 |
|---|---|---|
| 文章作者名 | ① 冗余 | D4 的 `author_name` |
| 文章封面 URL | ① 冗余（把域名内联） | D4 的 `buildCoverUrl` |
| 文章分类名 | ② 同步（同库 JOIN，还没跨库） | `complementArticleDTO` |
| 浏览量回写 | ③ 异步（Redis + 定时任务） | `ArticleReadCountTask` |

#### 决策一：作者名 —— 加冗余字段

**先确认过：`knowledge_article` 表里只有 `author_id`，没有 `author_name`。** 所以必须加。

```sql
ALTER TABLE mental_health_knowledge.knowledge_article
  ADD COLUMN author_name VARCHAR(64) DEFAULT NULL
  COMMENT '作者昵称（冗余，避免跨库查 user）' AFTER author_id;

-- 回填存量数据：旧库还在，可以直接跨 schema JOIN
UPDATE mental_health_knowledge.knowledge_article a
JOIN mental_health_assistant.user u ON u.id = a.author_id
SET a.author_name = IF(u.nickname IS NOT NULL AND TRIM(u.nickname) <> '',
                       u.nickname, u.username);
```

**进度（2026-10-28 16:10 实测）**：`author_name` 列**已经加好了**（varchar(64)，无 comment），7 篇文章值全为 NULL —— **只剩 UPDATE 回填这一条**。

`nickname` 为空回退到 `username`，和 `User.getDisplayName()` 的逻辑一致。当前数据里 `id=11` 的 nickname 是空串，正好会被回退成 `快乐的苟分仔2`，可以拿它验证 IF 分支。

⚠️ **关于反引号**：`USER` 在 MySQL 9.7 里 **`INFORMATION_SCHEMA.KEYWORDS.RESERVED = 0`，即不是保留字**，不加反引号也能跑。反引号是「防御性写法」（万一以后换库、或者列名撞上真保留字），不是必须。
真正的保留字查法：

```sql
SELECT WORD, RESERVED FROM INFORMATION_SCHEMA.KEYWORDS WHERE RESERVED = 1;
```

**代价（面试可以讲的点）**：用户改昵称后，旧文章的作者名不会自动变。要解决就得发 MQ 事件异步刷新 —— 这就是「最终一致」，也是 D9 拆 user-service 时 `user.changed` 事件的来源。

**备选方案（都更差，知道为什么不用）**：

| 前端不显示作者名 | 改前端 + 丢功能，最省事但最没价值 |

#### 决策二：封面 URL —— 内联，不要整个 OSSUtil

`OSSUtil.getUrl()` 只干一件事：把 objectKey 拼成完整 URL。原逻辑有三段（空值 → 已是 http 前缀原样返回 → 拼域名），照抄过来：

```java
@Value("${oss.bucket}") private String ossBucket;
@Value("${oss.region}") private String ossRegion;
@Value("${oss.domain:}") private String ossDomain;   // 可选 CDN

private String buildCoverUrl(String objectKey) {
    if (objectKey == null || objectKey.isBlank()) return null;
    if (objectKey.startsWith("http://") || objectKey.startsWith("https://")) return objectKey;
    String base = (ossDomain == null || ossDomain.isBlank())
            ? "https://" + ossBucket + ".oss-" + ossRegion + ".aliyuncs.com"
            : ossDomain;
    return base + "/" + objectKey.replaceAll("^/+", "");
}
```

knowledge-service 的 yml 补：

```yaml
oss:
  region: cn-beijing
  bucket: mental-health-ai-assistant
```

**为什么不复制整个 OSSUtil**：它还有 `upload` / `delete` 方法，依赖 `OSSClient` 和 AccessKey。knowledge-service 只读不写文件，复制过来等于把一整套凭证和客户端塞进一个不需要它的服务。**按需内联，比整体复制更干净。**

**D5 的两个 bug（已修复，详见第三节 D5 存档）**

**bug 1：`ArticleCommandDTO` 没有无参构造 → Jackson 反序列化失败**

`@Data` + `@Builder` 一起用时，Lombok 只生成全参构造，`@Data` 本该补的无参构造被抑制了。
`javap` 实测只有 6 个参数的构造器，Jackson 找不到无参构造 → 抛 `HttpMessageNotReadableException` → `4002`。

`ArticleStatusCommandDTO` 只有 `@Data`（没 `@Builder`），所以改状态能通；`ArticlePageQueryDTO` 是 query 参数绑定（走 setter），也不受影响。
—— 同一个包里的三个 DTO，只有一个坏，这就是「为什么只挂两个接口」的原因。

修法（DTO 上加两行）：

```java
@NoArgsConstructor
@AllArgsConstructor
```

> 另一个选择是给 Controller 参数加 `@RequestBody` 之外的 `@JsonCreator`，但没必要，加构造器注解最省事。

**bug 2：网关取 `X-User-Name` 的 claim 名写错，且用了 `toString()`**

```java
// 现在（错）
.header("X-User-Name", jwt.getClaim("userName").toString())
// 应该
.header("X-User-Name", jwt.getClaim("username").asString())
```

两处错：
- payload 里的 claim 叫 `username`（全小写），`userName` 取不到 → 返回 `NullClaim`
- 就算名字写对，`toString()` 也不给你干净的值：Claim 底层是 Jackson 的 `JsonNode`，`toString()` 走的是 JSON 打印 → 字符串会带引号

**实测对照（java-jwt 4.5.2，`ClaimTest.java` 跑出来的真值）**：

| 场景 | `asString()` | `toString()` |
|---|---|---|
| `getClaim("username")` | `admin` | `"admin"` ← 带双引号 |
| `getClaim("userName")`（不存在） | `null` | `Missing claim` |
| `getClaim("userId")`（数字） | `null` ← 取不到 | `1` |

所以不修的话，header 里写的是 `Missing claim`，`author_name` 就存成这串字面量。
—— 顺带说明：数字 claim 用 `asString()` 也拿不到，必须 `asLong()`/`asInt()`；`asXxx()` 是**按类型取值**，不是"转字符串"。

对照老代码 `JwtTokenUtil:109` 就是 `getClaim("username").asString()`。

不修的话 `author_name` 会写成字符串 `"null"`，前端作者列显示 null。

**AI 任务队列搬家的准确说法**（旧版写「会消费两次」，不准确）

`AiTaskConsumer` 用 `XREADGROUP` + 固定 group（`RedisKeys.AI_TASK_GROUP`），consumerName 是 `"work-"+UUID`。**同组内是分摊不是重复** —— 一条消息只会投给组内一个 consumer。所以默认情况下搬过去之后，一半任务归 8030、一半归 8080。

后果不是「算两遍」，而是三个更难查的现象：

1. 改完 8030 的代码，测试时「有时生效有时不生效」（另一半被旧代码吃了）
2. 30 秒一次的 pending 僵死消息重置，两个实例互相抢
3. 任务被 8080 消费时，8030 控制台一行日志都没有

**处理原则**：搬完必须停掉 web 侧的 `AiTaskConsumer`。分摊在这个场景下等同于 bug。

**consult-service 的 SSE 坑**

Gateway 默认会缓冲响应，SSE 流式输出会卡住。需要：

```yaml
spring:
  cloud:
    gateway:
      server:
        webflux:
          routes:
            - id: consult-service
              uri: lb://consult-service
              predicates:
                - Path=/api/consult/**
              filters:
                - DedupeResponseHeader=Access-Control-Allow-Origin
```

并在前端 `EventSource` 上确认 `Content-Type: text/event-stream` 透传。

### 5.3 Gateway

| 症状 | 原因 | 解法 |
|---|---|---|
| `Spring MVC found on classpath` | 引了 `starter-web` 或依赖了 common | 网关 pom 保持纯净 |
| `Binding to target GatewayProperties failed: uri Value "null"` | yml 写了 `url:` 而不是 `uri:` | 字段名是 `uri`；`ignoreUnknownFields=true` 会把 `url` **静默丢弃**，所以报错位置和出错位置隔很远 |
| 一堆 `configuration keys renamed` WARN | 4.3 起前缀改为 `spring.cloud.gateway.server.webflux.*` | 改前缀（不改也能跑，框架自动迁移） |
| `spring-cloud-starter-gateway is deprecated` | starter 改名 | 换 `spring-cloud-starter-gateway-server-webflux`，然后 **Reload Maven** |
| `LoadBalancer ... default cache` WARN | 用的是简陋 HashMap 缓存 | 加 `com.github.ben-manes.caffeine:caffeine`，零代码 |
| `lb://` 找不到实例 / 503 | 缺 loadbalancer，或网关的 namespace/group 与目标服务不一致 | 加依赖 + 核对 Nacos 三要素 |
| 网关过滤器完全不生效 | **忘了 `@Component`** | 加了之后会立刻暴露下一个错（占位符拼错） |
| 所有请求都放行 | 白名单里有 `"/"` | 删掉，或改用 `equals` 精确匹配 |
| 客户端能伪造身份 | 用了 `getHeaders().add()` | 用 `mutate().header()`（覆盖语义） |
| `X-User-Id` 是 null 但验签通过 | 用了 `asString()` 取数字 claim | 数字用 `asLong()` |
| `X-User-Name` 传下去是 `Missing claim` / 带引号的 `"admin"` | ① claim 名大小写写错（payload 是 `username`）② 用了 `toString()` 而不是 `asString()`。`toString()` 是 JSON 打印，字符串节点自带双引号，缺失节点打印 `Missing claim` | `jwt.getClaim("username").asString()`；**claim 名照抄老代码 `JwtTokenUtil`，别自己拼** |

### 5.4 拆模块 / 跨域

| 症状 | 原因 | 解法 |
|---|---|---|
| Move 之后两边一起红 | 跨模块不能互相依赖，Move 把依赖撕成两半 | **跨模块用 Copy**，老代码留着 |
| `@Cacheable` 静默不生效 | 缺 `@EnableCaching` | 检查 `CacheConfig` 是否复制 |
| `SerializationException: Cannot locate class 'org.example.aispringboot...'` | 两个服务共用同一个 Redis 缓存名，`GenericJackson2JsonRedisSerializer` 把类名写进了 value 的 `@class` | 缓存 key 加服务前缀（`computePrefixWith`），并清掉旧 key |
| 查不到的 id 也被缓存（如 `article::3` 存 null） | `unless` 写成 `#result!=null && ...`，结果为 null 时 `unless` 为 false → **null 被缓存** | 改成 `unless = "#result==null \|\| ..."` |
| 查不存在的 id 返回 500「系统繁忙」 | `unless` 写成 `#result==null && #result.status...`，null 时 `==` 为 true 继续求值右侧 → **SpEL 访问 null 的字段 → NPE** | 逻辑运算符是 **`\|\|`** 不是 `&&`：`#result==null \|\| #result.status!=...` |
| `SpelEvaluationException` 只在运行到缓存时抛 | `T(全限定名)` 是字符串，编译器不管 | 全局搜 `T(org.example.` 手动改包名 |
| `@AuthenticationPrincipal` 是 null | 服务内没有 SecurityContext | 换成 `@RequestHeader("X-User-Id")` |
| `POST`/`PUT` 返回 `4002 请求体格式不正确` | DTO 同时用了 `@Data` + `@Builder`。**`@Builder` 会隐式生成一个包级私有的全参构造器**（`build()` 要 new 对象），而 Lombok 发现类里已有构造器就不再生成 `@Data` 该补的无参构造 → 只剩全参 → Jackson 造不出对象 | DTO 上加 `@NoArgsConstructor @AllArgsConstructor`；`javap -p X.class \| grep 'X('` 一眼看出有几个构造器 |
| 「我一个 `@*ArgsConstructor` 都没加，哪来的全参构造」 | 就是 `@Builder` 自己加的，等价于 `@AllArgsConstructor(access = AccessLevel.PACKAGE)`。Lombok 官方文档原话：`@Builder` on a class is as if you added `@AllArgsConstructor(access = AccessLevel.PACKAGE)` | 别只看注解，看 `javap` 产物 |
| 「不是自动装填吗，为什么还要构造器」 | Jackson 两步走：**先 new 出对象，再 set 字段**。setter 填充是自动的，但 new 这一步必须有 Jackson 认识的入口（无参构造 / `@JsonCreator` / record）。全参构造不带 `@JsonCreator`，Jackson 不认 | 加无参构造就是给 Jackson 开个门 |
| 同包三个 DTO 只有两个接口挂 | 坏的那个带了 `@Builder`，另两个没有；query 参数走 setter 不走 Jackson | 别被「同一个包应该一起坏」误导，逐个看构造器 |
| `POST`/`PUT` 返回 `4002`，但 DTO 明明加了无参构造 | **curl 在 Git Bash 里发中文，body 不是合法 UTF-8**，Jackson 解析失败 | 改用 `--data-binary @file.json`（文件存 UTF-8）；先用纯 ASCII body 试一发，200 就说明是编码问题不是代码问题 |
| 分页 `total=0`、`pages=0`，records 却返回全部数据 | 缺 `MybatisPlusInterceptor` + `PaginationInnerInterceptor`。**没有它 `selectPage` 不报错**，只是不 count、不加 LIMIT，`getTotal()` 停在默认 0 | 复制 web 的 `config/MpConfig`；拆服务时 `ls config/` 整个目录过一遍，别凭记忆数配置类 |
| 分页参数 `size=2` 不生效、一页塞满所有数据 | 同上 | 同上；验证分页必须同时看「返回条数」和 `total`，只看条数会漏 |

### 7.3 D7 主线：diary-service 骨架 + 搬日记接口

#### 先看清这个域的真面目（跟直觉不一样）

日记**不在** `/api/diary/**`，也不是全在 `UserController` 里。它的 6 个接口全部挂在 `/api/emotion-diary` 下，**横跨两个 Controller**：

| 方法 | 路径 | 现在在 | 用途 |
|---|---|---|---|
| POST | `/api/emotion-diary` | UserController | 写日记 |
| GET | `/api/emotion-diary/page` | UserController | 我的日记分页 |
| PUT | `/api/emotion-diary/{id}` | UserController | 改日记 |
| DELETE | `/api/emotion-diary/{id}` | UserController | 删日记 |
| POST | `/api/emotion-diary/{id}/analyze` | UserController | 触发 AI 分析 |
| GET | `/api/emotion-diary/admin/page` | KnowledgeController | B 端看所有人的日记 |
| DELETE | `/api/emotion-diary/admin/{id}` | KnowledgeController | B 端删日记 |

**所以不能整文件 Copy**，要从两个 Controller 里各切一段 `/emotion-diary` 出来，拼成新的 `DiaryController`。

> 这是拆微服务的一条通用规律：**代码按「人怎么写」组织，服务按「业务边界」组织，两者从来不重合**。别指望一个 Controller 刚好对应一个服务 —— D3 搬 category 时运气好，这次不会。

#### 三个必须提前想清楚的点

**① 跨域依赖：`DiaryService` 要查 User 表**

`DiaryService:74` 有 `userMapper.selectBatchIds(userIds)`，第 80 行取 `User` 来填 B 端列表的「昵称/头像」。

**这跟 D4 的 `author_name` 是同一类问题**，方案也就那三选一：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐，D4 已打样）** | 冗余字段：`emotion_diary` 加 `user_name` / `user_avatar`，写入时从 `X-User-Name` 回填 | 改表 + 老数据刷一次 |
| B（最快） | B 端列表只显示 `user_id`，不显示昵称 | 功能退化，D11 拆完 user-service 再补 |
| C（别选） | 跨库 join user 表 | 库耦合，D11 还得拆一次 |

D7 当天如果想把「读接口通」先做出来，可以先走 B 把流程跑通，再补 A。**但别选 C**，那等于把已经拆掉的耦合又焊回去。

**② 网关路由顺序：`/api/emotion-diary/**` 必须排在 `/api/**` 之前**

现在兜底路由是 `/api/** → web(8080)`。新增日记路由时：

```yaml
- id: diary-service
  uri: lb://diary-service
  predicates:
    - Path=/api/emotion-diary/**
```

**这条必须写在 `id: web` 那条的前面。** Spring Cloud Gateway 按**配置里的顺序**逐个匹配，先命中即返回 —— 写到后面就永远命中不了，症状是「8030 明明起来了、Nacos 里也有实例、但请求还是打到 8080」，查起来极其费时。

**③ `@EnableScheduling` 要自己加**

web 的 `AiSpringbootApplication` 上有 `@EnableScheduling`，`AiTaskConsumer` 的三个 `@Scheduled` 全靠它。

diary-service 的主类如果忘了加：**编译不报错、启动不报错、日志也不报错**，只是定时任务永远不跑。表现是「日记写完，AI 分析永远没结果」。

今天不搬 consumer，但**主类先加上**，省得 D8 再查一遍。

### 7.6 D8 预告：AI 任务队列（旧说法要修正）

旧版这里写的是「两个服务消费同一个 Stream，任务会被消费两次」——**不准确**。

`AiTaskConsumer` 用的是 `XREADGROUP` + 同一个 group（`RedisKeys.AI_TASK_GROUP`），而 `consumerName` 是 `"work-"+UUID`（每个实例随机）。

Redis Stream 消费者组的语义是：**同组内不同 consumer 分摊消息，一条消息只投给其中一个**。所以：

| 情况 | 结果 |
|---|---|
| 同 group、不同 consumerName（默认） | **不重复消费**，是**分摊** —— 一半日记被 8030 处理，一半被 8080 处理 |
| 不同 group | 才是真重复，两边各算一遍 |

那搬完之后真正的风险是什么：

1. **行为不可预测** —— 你改完 8030 的代码，测试时「有时生效有时不生效」，因为一半任务还在旧代码里跑
2. **pending 互相抢** —— `AiTaskConsumer` 有个 30 秒扫僵死消息的定时任务（`STALE_SECONDS`），两个实例会同时扫同一批 pending
3. **日志看不见** —— 任务被 8080 吃了，你在 8030 控制台等不到任何输出

**结论**：D8 搬完 consumer，**web 侧必须停掉**（`@Component` 或 `@Scheduled` 注掉都行）。别用「同 group 会自动分摊所以无所谓」安慰自己 —— 分摊在这个场景下就是 bug。

## 八、附：踩过的坑（D5~D6 补记）

1. `@Data` + `@Builder` 共存会吃掉无参构造 → `4002`，同一个包里的 DTO 只有一个中招
2. JWT claim 名照抄老代码，别凭记忆写 `userName`；字符串 claim 用 `asString()` 不用 `toString()`
3. **curl 发中文 → `4002` 不一定是代码问题**，先排除终端编码（用 `--data-binary @file.json`）
4. **`selectPage` 少了分页插件不报错**，只是静默地不 count、不加 LIMIT
5. **`git add -A` 不会提醒你漏了新增文件**。`MpConfig.java` 就是这么被 D5 的提交漏掉的 —— 提交后用 `git show --stat HEAD` 点名核对新文件
6. **`No servers available for service: xxx` 不是「没注册」，是「查不到可用实例」**。可能是没起、起在别的 namespace、或注册刚发生但 LoadBalancer 缓存还没刷
7. **「我打开 Nacos 网页登录了一下就好了」是巧合，不是因果。** 服务发现走 8848 的 gRPC 长连接，跟 8888 控制台毫无关系。真实过程是注册推送 + LoadBalancer 本地缓存刷新要几秒到几十秒，你折腾网页的那点时间刚好够它自己恢复。**下次遇到：先确认实例在不在，在就等 30 秒，别重启网关**
8. **前端锁必须在 `validate()` 之前上，解锁必须在 `finally`**。异步校验之间存在穿透窗口；而 `.then` 里有提前 `return` 的路径会跳过解锁，锁就永远解不开了
9. **`:loading` 挡不住键盘事件**。它只挡鼠标点击，`keyup` 挂在表单上不经过按钮。逻辑锁和视觉反馈是两套机制，缺一不可
10. **Vite 的 proxy target 改动要重启 dev server**，HMR 只管源码不管配置文件
